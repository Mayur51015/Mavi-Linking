# Code of Conduct

## Our Commitment

We are committed to providing a welcoming, respectful, inclusive, and
harassment-free environment for everyone participating in this project.

All contributors, maintainers, reviewers, users, and community members
are expected to behave professionally and respectfully.

## Expected Behavior

Participants are expected to:

- Be respectful and professional.
- Communicate constructively and politely.
- Welcome contributors with different experience levels.
- Give and receive constructive feedback.
- Focus on the technical issue rather than the individual.
- Respect different opinions, approaches, and backgrounds.
- Help maintain a friendly and collaborative environment.
- Give proper credit to other contributors.
- Follow the project's contribution and issue-assignment guidelines.
- Respect maintainer decisions while remaining free to discuss technical
  concerns constructively.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, discrimination, intimidation, or personal attacks.
- Trolling or deliberately disruptive behavior.
- Insulting or humiliating other contributors.
- Threats or abusive language.
- Sexual harassment or unwanted sexual attention.
- Publishing someone's private or personal information without permission.
- Sharing passwords, API keys, tokens, or other sensitive information.
- Deliberately introducing malicious code or security vulnerabilities.
- Spam or excessive self-promotion.
- Creating duplicate work intentionally after an issue has been assigned.
- Misrepresenting someone else's work as your own.
- Any other behavior that would reasonably make another participant feel
  unsafe or unwelcome.

## Contribution Guidelines

Before contributing:

1. Check the existing issues and pull requests.
2. Avoid duplicating work that is already assigned.
3. Comment on an issue if you would like to work on it.
4. Wait for maintainer confirmation before starting significant work.
5. Follow the project's contribution guidelines.
6. Submit focused and properly tested pull requests.
7. Respond respectfully to code review feedback.

### Issue Assignment

Submitting `/claim` does not automatically guarantee assignment.

When multiple contributors are interested in an issue, maintainers may
consider:

- Relevant technical skills.
- Previous contributions.
- Understanding of the issue.
- Proposed implementation approach.
- Availability and ability to complete the task.

Maintainers aim to provide fair opportunities while ensuring that issues
are assigned to contributors who are a good fit for the task.

## Security and Privacy

Do not publicly post:

- Authentication tokens.
- Passwords.
- API keys.
- Private user information.
- Private documents.
- Session cookies.
- Production credentials.
- Sensitive security vulnerability details.

If you discover a security vulnerability, report it privately through
the project's security reporting process rather than publicly exposing
the vulnerability.

## Pull Request Conduct

Pull requests should:

- Clearly explain the changes.
- Reference the related issue.
- Contain only relevant changes.
- Include appropriate tests where applicable.
- Follow the project's coding standards.

If you experience or witness behavior that violates this Code of Conduct,
please report it privately to the project maintainers.

When making a report, provide as much relevant information as possible,
including what happened, when it happened, and where it occurred.

Please do not publicly share private information, credentials, or sensitive
